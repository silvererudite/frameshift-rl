Research note · DNA × RL · Qwen3-0.6B

Does RL fix what the tokenizer breaks?

DNA models like Carbon-X read sequences as multi-base tokens, yet tasks like reverse complement work base by base. I trained the same small language model with GRPO on the same DNA tasks, changing only how the sequence is cut into tokens, to see whether RL can learn around the segmentation.

TL;DR
  • Exact-match reward gives no learning signal. 0 of 4,568 reverse-complement training rollouts were correct in any format, so every GRPO group had zero variance and zero gradient.
  • Partial-credit reward gets gamed. The policy learned to copy the input verbatim: 88% (raw), 98% (per-base), 74% (6-mer) of answers after RL, up from 8%, 17% and 5%. A copy always has the right length and scores ~25% by chance.
  • The format changed how faithfully the model copies, not whether it can reverse-complement. Errors sit at chance (~75% per base) at token edges and inside tokens alike.
  • A DNA-trained model has the skill, and its errors follow its tokenizer. Carbon-X reverse-complements 68.5% of the same prompts exactly, counts GC right only ~10%, and drops from ~80% to 44% accuracy as its padded leftover 6-mer chunk grows.

Where the errors happen

For reverse-complement answers with the right length, each wrong output base is traced back to the input base it should copy. The question is whether that input base sat at the edge of a token or inside one.

Setup & limitations

Model: Qwen3-0.6B (fp32) + LoRA r=16 on all linear projections, non-thinking chat template. RL: GRPO (TRL), 8 generations per prompt, 4 prompts per step, β=0, lr 2e-5, exact-match reward (1/0), no partial credit. Tasks: reverse complement and GC count on random 12–90 bp sequences (procedural, in the style of FineDNA's rl_mix basic-operation tasks). Eval: 240 held-out prompts (2 tasks × 3 length buckets × 40), 4 samples each (T=0.7, top-p 0.8), same sequences in every format. Compute: Kaggle, 2× T4.

Limitations: single seed; a short RL run with a wall-clock cap; a small vanilla model with a simulated 6-mer view, not Carbon-X itself; LoRA rather than full fine-tuning; two synthetic tasks.
